# 仕様

worktree-cleaner はローカルの Git リポジトリに登録された linked worktree を列挙し、リポジトリ名、パス、判定、理由を表示する。
探索の起点はカレントディレクトリまたは `--root` で指定したディレクトリとする。
リポジトリ内ならそのリポジトリを、リポジトリ外なら直下の主 worktree を調べる。
登録先が起点の外でも判定対象に含める。

既定の削除候補は、基準ブランチに取り込まれたローカルブランチ上の clean な linked worktree とする。
基準は各リポジトリの origin/HEAD に対応するローカルブランチ、または `--base` で指定したローカルブランチとする。
既定ではロック、作業中の変更、無視ファイルを含む未追跡ファイル、入れ子のリポジトリ、サブモジュール、進行中の Git 操作があれば保持する。
主 worktree、基準ブランチ自身、現在地を含む worktree、判定に失敗した worktree も保持する。

既定では一覧を表示する。
`--remove PATH` は探索範囲内の一件、`--remove-all` は探索範囲内の全候補について削除直前に再検査し、候補の作業ディレクトリと登録を削除する。
ブランチ参照は保持する。
再検査から削除が終わるまでは、対象での並行作業を止める必要がある。
判定条件とテスト設計は [ADR 0001](adr/0001-worktree-cleanup.md) に記載する。

`--include-unmerged` は、未マージの HEAD を同じローカルブランチで保持でき、ほかの保護条件を満たす worktree を候補に加える。
削除直前にブランチ名とコミット ID を照合し、削除後もブランチを保持する。
追加条件は [ADR 0002](adr/0002-include-unmerged-worktrees.md) に記載する。

`--github-merged` を指定すると、ローカルで未マージと判定した clean なブランチについて gh で GitHub.com に問い合わせる。
現在の HEAD とマージ済み PR の先端、対象リポジトリ、基準ブランチが一致し、PR のマージコミットがローカルの基準から到達可能な場合を統合済みと扱う。
削除前には同じ証拠を再取得する。

`--reclaim-agent-locks` は同じ Mac で作成した専用の作業ディレクトリを対象とする。
認識できる Claude エージェントのロックで、所有者の終了とブランチの統合を確認できた場合に限り、削除時に解除する。
開始時刻にはタイムゾーンが記録されないため、PID 再利用の証拠には新旧の開始日時に 48 時間を超える差を求める。
解除後に保護条件が変われば保持し、削除失敗時には残った同じ登録に元のロックを復元する。
ほかのプロセスによる同時操作を止めて実行する。
判定と復旧の条件は [ADR 0003](adr/0003-reclaim-agent-locks-and-check-merged-prs.md) に記載する。

削除候補の一件が再検査や削除に失敗しても、理由を keep 行に出して残りの候補を処理する。
部分削除の可能性と登録の残存状態、ロック復旧の結果を理由欄に含める。
削除処理後に試行、削除完了、失敗の件数を標準エラーに出し、一件以上失敗していれば終了コード 1 を返す。
初回検査で保持された対象は試行件数に含めない。
標準出力への書き込み失敗時には後続の削除を停止する。
一覧操作と候補選択自体の失敗では削除結果の集計を出さない。
詳細は [ADR 0004](adr/0004-continue-after-removal-failure.md) に記載する。
