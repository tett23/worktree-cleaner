# 仕様

worktree-cleaner はローカルの Git リポジトリに登録された linked worktree を列挙し、リポジトリ名、パス、判定、理由を表示する。
探索の起点はカレントディレクトリまたは `--root` で指定したディレクトリとする。
リポジトリ内ならそのリポジトリを、リポジトリ外なら直下の主 worktree を調べる。
登録先が起点の外でも判定対象に含める。

既定の削除候補は、基準ブランチに取り込まれたローカルブランチ上の clean な linked worktree とする。
基準は各リポジトリの origin/HEAD に対応するローカルブランチ、または `--base` で指定したローカルブランチとする。
`--remote-base` を指定したときは、後述のとおり origin のリモート追跡ブランチを基準にする。
既定ではロック、作業中の変更、無視ファイルを含む未追跡ファイル、入れ子のリポジトリ、サブモジュール、進行中の Git 操作があれば保持する。
主 worktree、基準ブランチ自身、現在地を含む worktree、判定に失敗した worktree も保持する。

既定では一覧を表示する。
`--remove PATH` は探索範囲内の一件、`--remove-all` は探索範囲内の全候補について削除直前に再検査し、候補の作業ディレクトリと登録を削除する。
ブランチ参照は保持する。
再検査から削除が終わるまでは、対象での並行作業を止める必要がある。
判定条件とテスト設計は [ADR 0001](adr/0001-worktree-cleanup.md) に記載する。

既定では、最近 Git の管理ファイルが更新された worktree も保持する。
最終操作時刻は、管理ディレクトリ（`<共通ディレクトリ>/worktrees/<名前>`）の `HEAD`、`index`、`logs/HEAD` のうち、存在するファイルの更新時刻の最新とする。
経過は、検査の時点の現在時刻から最終操作時刻を引いた長さとする。
`--min-idle <時間数>` は、この保護の期間を 0 以上の十進の整数の時間数で指定し、既定は 24 とする。
経過がその時間数に満たない worktree と、最終操作時刻が現在時刻より後の worktree は保持する。
3 つのファイルがどれもない worktree と、存在するファイルの更新時刻を読めない worktree も保持する。
理由欄には、経過を切り捨てた時間数か、保持の原因を出す。

この保護の検査は、ロックの検査の後、基準の解決の前に行う。
そのため、最近の操作がある worktree は、detached HEAD、基準ブランチ自身、基準の解決の失敗、未マージ、clean でない、のどれに当たってもこの理由で保持する。
削除の直前の再検査では、現在時刻を読み直して同じ判定を行う。

`--min-idle 0` はこの保護を使わず、ファイルの更新時刻も読まない。
`--min-idle` の値が数字だけの並びでないとき（`-1`、`+1`、`1.5`、`24h`、空など）と、64 ビットの符号なし整数にあふれるときは、一覧も削除もせずに終了コード 1 で終わる。
判定条件は [ADR 0010](adr/0010-keep-recently-active-worktrees.md) に記載する。

`--include-unmerged` は、未マージの HEAD を同じローカルブランチで保持でき、ほかの保護条件を満たす worktree を候補に加える。
削除直前にブランチ名とコミット ID を照合し、削除後もブランチを保持する。
追加条件は [ADR 0002](adr/0002-include-unmerged-worktrees.md) に記載する。

`--allow-ignored` を指定すると、無視ファイルを保持の理由にしない。
インデックスにないファイルがすべて無視され、ほかの保護条件を満たす worktree を候補にし、削除では無視ファイルごと作業ディレクトリを消す。
無視されない未追跡ファイル、作業中の変更、無視されたディレクトリの中の入れ子のリポジトリと特別なファイルがあれば、指定しても保持する。
指定したときは、候補と削除の行の理由に、削除する無視ファイルの数を `; deletes N ignored files` の形で添える。
数は、作業ディレクトリのルートの `.git` を除く、インデックスにないファイルとシンボリックリンクの数とし、無視ファイルがなければ 0 とする。
削除直前の再検査でも同じ判定をし、無視されない未追跡ファイルが増えていれば保持する。
数は表示だけに使い、選択から削除までの照合には使わない。
`--include-unmerged`、`--github-merged`、`--reclaim-agent-locks` と組み合わせられる。
指定しないときの判定は変わらない。
詳細は [ADR 0008](adr/0008-allow-ignored-files.md) に記載する。

`--github-merged` を指定すると、ローカルで未マージと判定した clean なブランチについて gh で GitHub.com に問い合わせる。
現在の HEAD とマージ済み PR の先端、対象リポジトリ、基準ブランチが一致し、PR のマージコミットが基準から到達可能な場合を統合済みと扱う。
削除前には同じ証拠を再取得する。

`--remote-base` を指定すると、各リポジトリで基準の名前を同じ方法で決め、到達の判定には `refs/remotes/origin/<名前>` を使う。
この参照は利用者が最後に fetch した時点の値であり、worktree-cleaner は fetch もローカルの基準ブランチの更新も行わない。
`origin/<名前>` に取り込まれた worktree の理由は `clean and integrated into origin/<名前>` と表示する。
HEAD が `refs/heads/<名前>` を指す worktree は、ローカルブランチ `<名前>` の有無にかかわらず保持する。
`refs/remotes/origin/<名前>` がないリポジトリの worktree は理由を示して保持し、ほかのリポジトリの処理を続ける。
`--include-unmerged` と組み合わせると、`origin/<名前>` から到達できない HEAD を未マージとして扱う。
`--github-merged` と組み合わせると、GitHub に渡す基準の名前は `<名前>` とし、PR のマージコミットが `origin/<名前>` から到達可能であることを求める。
削除直前の再検査でも同じ参照を使う。
指定しないときの判定は変わらない。
詳細は [ADR 0009](adr/0009-remote-tracking-base.md) に記載する。

`--reclaim-agent-locks` は同じ Mac で作成した専用の作業ディレクトリを対象とする。
認識できる Claude エージェントのロックで、所有者の終了とブランチの統合を確認できた場合に限り、削除時に解除する。
開始時刻にはタイムゾーンが記録されないため、PID 再利用の証拠には新旧の開始日時に 48 時間を超える差を求める。
解除後に保護条件が変われば保持し、削除失敗時には残った同じ登録に元のロックを復元する。
ほかのプロセスによる同時操作を止めて実行する。
判定と復旧の条件は [ADR 0003](adr/0003-reclaim-agent-locks-and-check-merged-prs.md) に記載する。

削除候補の一件が再検査や削除に失敗しても、理由を keep 行に出して残りの候補を処理する。
部分削除の可能性と登録の残存状態、ロック復旧の結果を理由欄に含める。
削除処理後に試行、削除完了、失敗の件数を標準エラーに出し、一件以上失敗していれば終了コード 1 を返す。
初回検査で保持された対象は試行件数に含めない。
標準出力への書き込み失敗時には後続の削除を停止する。
一覧操作と候補選択自体の失敗では削除結果の集計を出さない。
詳細は [ADR 0004](adr/0004-continue-after-removal-failure.md) に記載する。
