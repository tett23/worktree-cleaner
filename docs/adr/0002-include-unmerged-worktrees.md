# ADR 0002: 明示指定で未マージのブランチの作業ディレクトリを片付ける

ステータス: 採択

## 文脈

未マージのコミットを残したまま、作業ディレクトリだけを片付けたい場合がある。
[ADR 0001](0001-worktree-cleanup.md) の不変条件 5 は、ローカルブランチの先端が基準ブランチから到達できる場合だけを候補にする。
一方、不変条件 13 により、worktree を削除してもブランチ参照は残る。
そこで、コミット済みの内容をローカルブランチから再びチェックアウトできる場合に限り、利用者が削除範囲を広げられるようにする。

## 調査した事項

2026 年 11 月 11 日に、インストール済みのコマンドで `~/repositories/src/github.com/tett23/worktree-cleaner` から親ディレクトリ配下を再集計した。
`worktree-cleaner --root ..` の結果は 67 件で、表示された最初の保持理由は次のとおりだった。

| 最初の保持理由 | 件数 |
| --- | ---: |
| ブランチが未マージ | 31 |
| インデックスまたは作業ディレクトリに変更あり（未追跡、無視ファイルを含む） | 15 |
| ロックあり | 11 |
| detached HEAD | 10 |

未マージの 31 件について、各 worktree で `git --no-optional-locks status --porcelain --ignored --untracked-files=normal` を実行した。
出力が空だったのは 9 件で、残りの 22 件にはファイルまたはインデックスに保持理由があった。
一時コピーで未マージのローカルブランチを後続の検査に通し、同じ起点で一覧だけを実行すると、元の 31 件のうち 9 件が候補になった。
この件数は調査時に二つの一覧で照合できた結果であり、将来の削除件数は作業状態によって変わる。

detached HEAD の 10 件では、いずれも HEAD が基準ブランチの祖先または同じコミットだった。
一時コピーでその場合も後続の検査に通したが、この 10 件から候補は増えなかった。

## 実装すること

`--include-unmerged` を指定すると、基準ブランチに未マージでも、HEAD のコミットを同じローカルブランチの参照で保持できる worktree を候補に加える。
一覧では、この追加条件で選んだ行に、未マージであることと削除後に残るブランチ名を表示する。
例えば、親ディレクトリで `worktree-cleaner --include-unmerged` を実行すれば、削除範囲を広げた結果を確認できる。
一括削除には `worktree-cleaner --include-unmerged --remove-all` を使う。

## アルゴリズム

各 worktree で従来どおり基準ブランチと HEAD を解決し、コミットの到達可能性を調べる。
到達できないことを確認した場合にだけ追加条件を評価する。
解決前の HEAD 参照を読み、その直接のシンボリック参照先が refs/heads/ 配下にあり、そのブランチが直接指すコミット ID と HEAD のコミット ID が一致することを確かめる。
続いて従来と同じ clean 判定と保護条件を適用する。
削除操作では、初回判定で候補の種別（従来または追加）、ブランチ名、コミット ID を記録する。
削除直前に再判定し、初回または再判定で追加条件を使う場合は、記録したブランチ名とコミット ID がともに一致するときだけ削除する。

## 実装しないこと

無視ファイルの一括削除、ロック解除、detached HEAD の対象化は今回の範囲に含めない。
コミット済みの内容が基準ブランチに統合済みかどうかを、パッチの類似性から推定する機能も対象外とする。

## 不変条件

1. オプションを省略すると、一覧、単一削除、一括削除の候補集合はいずれも従来と一致する。
2. オプション指定時の追加候補は、到達可能性だけを理由に従来の条件から外れ、上記のブランチ参照で HEAD のコミットを保持できる worktree に限る。基準未解決や到達可能性検査のエラーは保持とする。
3. 追加候補を一覧に表示しても、ファイル、登録、ブランチ参照を変更しない。
4. 初回または削除直前に追加条件を使う場合、ブランチ名またはコミット ID が初回判定と異なる worktree は保持する。
5. 追加候補を削除した後も、元のローカルブランチ名は削除直前と同じコミット ID を指す。

ほかの条件を満たす場合の境界を示す。

| 入力 | 指定なし | 指定あり |
| --- | --- | --- |
| 基準にないコミットが 0 件 | 従来の候補 | 従来の候補 |
| 基準にないコミットが 1 件 | 保持 | 追加候補 |
| 同じ未マージの HEAD が detached | 保持 | 保持 |
| 未マージで無視ファイルが 1 件 | 保持 | 保持 |
| 未マージでロックあり | 保持 | 保持 |
| 基準が解決できない | 保持 | 保持 |

## テスト設計

テスト名にこの ADR の不変条件番号を入れる。
条件 1 と 2 は一時リポジトリで境界表を再現し、一覧、単一削除、一括削除の各操作で対象が一致することを検証する。
条件 2 では到達可能性検査のエラー、基準ブランチ自身、現在地、ステージ済み変更、未追跡ファイル、サブモジュールも個別に試す。
条件 3 は一覧の理由に未マージとブランチ名が含まれること、および一覧前後の登録と参照の一致を検証する。
条件 4 は候補選択後に同じコミットの別ブランチへの切り替え、同じブランチの先端更新、ファイルの追加を個別に試す。
条件 5 は未マージのコミットを一つ作り、削除後に同じブランチから新しい worktree を作って追跡ファイルの内容を照合する。

## トレードオフ

clean な作業ディレクトリでも、利用者がそこで作業を続ける予定は Git の状態から判断できない。
そのため、追加条件は実行ごとの明示指定とし、既定の一括削除では従来の判定を使う。
再チェックアウトで復元できる範囲はブランチに記録された内容であり、作業ディレクトリのパスや worktree 固有の HEAD reflog は削除される。
